# 2026-07-09 采购单提交窗口精准修复

## 范围
- 只修改库存管理下的采购订单提交交互。
- 只补充对应数据安全测试。
- 未修改 POS、员工、财务、供应商等其他业务逻辑。

## 问题
采购入库新建采购单提交后，窗口仍停留在页面上。用户容易误以为没有提交成功，再次点击提交，造成同一票号或同一采购内容重复。

## 修复
- 提交按钮通过基本校验后立即锁定，防止连续点击。
- 校验通过后立即关闭采购单窗口并清空表单，不等待云端写入完成。
- 云端写入成功后再弹出“采购单 xxx 云端写入成功”确认。
- 云端写入失败时提示失败，并保留刚才提交的草稿，方便重新打开后核对重试。
- 本地缓存写入改为非阻塞，避免 localStorage 或缓存问题导致窗口不关闭。
- 增加本地同票号拦截，避免同一窗口重复提交同一采购单号。

## 验证
- `npm test -- --watchAll=false --runInBand src/utils/dataSafety.test.ts --testNamePattern "purchase order"`
- `npm test -- --watchAll=false --runInBand src/utils/dataSafety.test.ts`
- `npm run build`

## 注意
- 本次没有删除历史重复采购单，比如用户提到的 `0708`，避免误删真实业务数据。
- 如需删除重复采购单，需要先确认要删除的具体云端记录。
